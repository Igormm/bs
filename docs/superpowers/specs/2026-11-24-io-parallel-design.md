# io::parallel — дизайн / design

Дата / Date: 2026-11-24  
Статус / Status: proposed  
Ярус / Tier: `@shell bash4,zsh`

## 1. Назначение / Purpose

`lib/io/parallel.sh` предоставляет ограниченный параллельный запуск задач для
bash 4.2+ и zsh. Модуль решает две задачи:

- `map` — вызвать один callback для каждого входного элемента;
- `run` — выполнить список shell-команд из файла, одна команда на строку.

Модуль не является планировщиком на будущее (`at`/`cron` остаются в
`lib/system/schedule.sh`) и не дублирует жизненный цикл одного процесса
(`lib/io/process.sh`).

## 2. API

```bash
load "lib/io/parallel"

io::parallel::map --jobs 4 --out-dir results \
    --scheduler pid -- my_worker item1 item2 item3

io::parallel::run --jobs 4 --out-dir results \
    --scheduler fifo -- tasks.txt
```

### Общая грамматика / Common grammar

- `--jobs N` — положительное целое, обязательное.
- `--out-dir DIR` — обязательный каталог результатов.
- `--scheduler pid|fifo|xargs` — необязательный, default `pid`.
- `--` — единственный разделитель конца опций.
- После `--` идут позиционные аргументы.

### `map`

- Первый позиционный аргумент — callback (имя функции или команда).
- Каждый следующий позиционный аргумент передаётся callback **одним аргументом**.
- Фиксированные дополнительные аргументы callback в v1 не поддерживаются.
- Пустой список элементов допустим: создаётся `out-dir`, общий статус `0`.

### `run`

- Единственный позиционный аргумент — путь к файлу задач.
- Каждая непустая строка файла выполняется через `bash -c`.
- Строки-комментарии, начинающиеся с `#`, игнорируются.
- Файл задач является shell-кодом по явному контракту; вызывающий отвечает за
  доверие к его содержимому.

## 3. Результаты / Results

Для нулевого индекса задачи `N` создаются:

```text
<out-dir>/NNNN.out
<out-dir>/NNNN.err
<out-dir>/NNNN.rc
```

- `NNNN` — десятичный индекс с нуля, минимум четыре цифры.
- `.out` — stdout воркера.
- `.err` — stderr воркера.
- `.rc` — код возврата воркера одной строкой.
- Порядок индексов совпадает с порядком входных данных.
- `map`/`run` не пишут ничего в stdout.
- Общий статус: `E_SUCCESS` (`0`), если все `.rc` равны `0`; иначе `E_ERROR`.
- Все задачи завершаются; fail-fast в v1 отсутствует.

## 4. Планировщики / Schedulers

Все реализации используют общий worker wrapper и общий формат результатов.

### 4.1 `pid` (default)

- Массив активных PID.
- Не более `--jobs` процессов одновременно.
- Слот переиспользуется после `wait` завершившегося PID.
- Не использует `wait -n`, поэтому совместим с bash 4.2.
- Возможна недогрузка, если ранний PID работает дольше остальных; это принято
  как цена простоты и нулевых внешних зависимостей.

### 4.2 `fifo`

- PID-pool + именованный канал завершений.
- Воркер пишет индекс завершившейся задачи в FIFO.
- Родитель читает индекс, ждёт соответствующий PID и переиспользует слот.
- Требует `mkfifo`; при отсутствии возвращается `E_ERROR`.
- Внутренний FIFO создаётся во временном каталоге и удаляется при cleanup.

### 4.3 `xargs` (заглушка / stub)

- Значение `--scheduler xargs` распознаётся парсером.
- Реализация намеренно отсутствует: `map` и `run` возвращают `E_ERROR` с
  сообщением «not implemented».
- Заглушка не запускает процессы, не создаёт `out-dir` и не пишет результатов.
- Разработка этого направления входит в отдельную будущую задачу.

## 5. Совместимость bash4/zsh

Модуль помечается:

```bash
# @shell bash4,zsh — массивы и job control; zsh работает через KSH_ARRAYS/SH_WORD_SPLIT
```

При загрузке в zsh включаются:

```bash
setopt KSH_ARRAYS SH_WORD_SPLIT no_nomatch
```

Запрещены:

- `local -n` / nameref;
- `printf -v`;
- `mapfile`;
- `wait -n`;
- `${!array[@]}`;
- предположение о word splitting без явного контракта.

Допустимы:

- индексированные массивы с индексацией от нуля;
- фоновые задачи и `wait PID`;
- временные файлы и FIFO;
- `local` и `[[ ]]`.

## 6. Ошибки и cleanup / Errors and cleanup

- Невалидное значение `--jobs` или неизвестный `--scheduler` → `E_INVALID`.
- Отсутствуют обязательные аргументы → `E_INVALID`.
- Недоступен `mkfifo` → `E_ERROR`; заглушка `xargs` → `E_ERROR` без побочных
  эффектов.
- Ошибка отдельного воркера не останавливает остальные.
- SIGINT/SIGTERM завершают активных PID, сохраняют уже созданные результаты и
  возвращают ненулевой статус.
- Внутренние временные файлы/FIFO удаляются; `--out-dir` не удаляется.
- Функции модуля не вызывают `exit`.

## 7. Безопасность / Security

- Элементы `map` передаются как позиционные аргументы, без `eval`.
- `run` намеренно использует `bash -c` для shell-команд; это документированная
  граница доверия.
- Имена путей и каталогов всегда кавычатся.
- Временный каталог создаётся через `mktemp -d` с проверкой результата.
- PID валидируются как положительные числа перед `kill`/`wait`.

## 8. Тестирование / Testing

`tests/unit/testparallelunit.sh` запускается в bash и zsh и проверявает:

1. `map` сохраняет stdout/stderr/rc каждого элемента отдельно.
2. Индексы соответствуют порядку входных элементов.
3. Одновременно выполняется не более `--jobs` задач.
4. Ненулевой rc одной задачи не мешает остальным; общий rc ненулевой.
5. Пустой список элементов возвращает успех.
6. `run` исполняет построчно команды из файла.
7. `pid` и `fifo` дают одинаковый контракт результатов.
8. `xargs` возвращает `E_ERROR`, не создаёт процессов и результатов.
9. Невалидные аргументы возвращают `E_INVALID`.
10. Отсутствие `mkfifo` моделируется через `PATH`-хук.
11. Прерывание завершает активные задачи и очищает внутренние временные файлы.

Дополнительно:

- `bash -n` и `shellcheck -s bash --severity=error`;
- реальный запуск примера `examples/parallel_demo.sh` в bash и zsh;
- полный validation cycle перед коммитом.

## 10. Не входит в v1 / Out of scope

- реализация `xargs -P`;
- callback с фиксированными дополнительными аргументами;
- fail-fast;
- возврат результатов в caller-named массивы;
- сетевое распределение задач;
- автоматическое определение оптимального `--jobs`;
- интеграция с `at`/`cron`.

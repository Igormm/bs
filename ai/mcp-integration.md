# AI integration ideas for BS

This document collects ideas for integrating the BS framework with AI tools, MCP servers, API providers and CI pipelines.

## Model Context Protocol (MCP)

An MCP server for BS could expose the following tools to an AI agent:

| Tool | Purpose |
|------|---------|
| `bs_doctor` | Run `bs doctor` and return the health report. |
| `bs_list` | List available modules (`bs list`). |
| `bs_run` | Execute a BS script: `bs run <script> [args...]`. |
| `validate_syntax` | Run `bash tests/validatesyntax.sh`. |
| `validate_shellcheck` | Run `bash tests/validateshellcheck.sh`. |
| `run_tests` | Run `bash tests/runalltests.sh`. |
| `read_module` | Read a module file and its tests for context. |
| `read_style_guide` | Return the BS code-style guide. |

### Benefits

- The model can verify its own output by calling validators.
- Agents stay within the framework's conventions because `AGENTS.md` and style guides are available as resources.
- Tests provide immediate feedback, enabling iterative self-correction.

## API provider integration

Any LLM with function calling can drive BS development:

1. The user describes a feature or bug.
2. The model generates a draft module or patch.
3. The agent writes the draft to the working tree.
4. The agent calls `validate_syntax`, `validate_shellcheck`, and `run_tests`.
5. If errors are reported, the model receives the output and produces a fix.
6. The loop continues until all validators pass.

### Suggested system prompt fragment

```text
You are an expert Bash developer working with the BS framework.
Before writing code, read AGENTS.md and the relevant code-style guide.
After every change, run the validators in tests/.
Keep changes minimal and add or update tests for new behavior.
```

## CI integration

Add a dedicated CI job that runs when AI-generated branches are pushed:

```yaml
ai-review:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4
    - name: Syntax check
      run: bash tests/validatesyntax.sh
    - name: ShellCheck
      run: bash tests/validateshellcheck.sh
    - name: Unit tests
      run: bash tests/runalltests.sh
```

Consider also a `diff-quality` check that compares the changed files against `AGENTS.md` rules (for example, ensuring new modules use `bs::guard`).

## Security considerations

- Never let an AI execute arbitrary shell commands without human review.
- Run AI-generated scripts in isolated environments or containers first.
- Do not expose secrets (tokens, SSH keys) to the AI context.
- Keep `.env` and sensitive files out of the model's context window.
- Validate all file paths generated by the agent to prevent writes outside the repository.

## Context compression

For large repositories, feed the model only the relevant subset:

- `AGENTS.md`
- `ai/lib-prompt.md` or `ai/core-prompt.md`
- `documentation/{ru,en}/code-style-guide.md`
- The target module and its tests
- Modules listed in `# @depends` comments

This keeps token usage low while preserving the conventions the model needs.

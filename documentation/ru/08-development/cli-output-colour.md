# Цвет вывода CLI

Как находить места, где BS печатает текст, и красить нужные части без
догадок. Коротко: цвет — это **роль**, а не украшение, и проверка терминала
делается **один раз**, а не там, где собирается строка.

## 1. Найти места вывода

Скрипт-инвентарь перечисляет все прямые команды вывода (`printf`, `echo`,
`print`, `printn`, `eprint`, `eprintn`, `tty_print`) и отделяет те, что уже
используют helper, от «голых»:

```bash
sh scripts/check_output_color.sh                       # bootstrap/cli.sh + lib/
sh scripts/check_output_color.sh --list                # каждая неокрашенная команда
sh scripts/check_output_color.sh --list bootstrap/cli.sh
sh scripts/check_output_color.sh --all lib             # включая движки
```

Команда считается окрашенной, если в логической строке (продолжения через `\`
склеиваются) есть `bs_cli_paint`, `bs_log_*`, `presentation::*`, `tui::*`,
`wiz::*`, константа `COLOR_`/`PRESENTATION_*`, `bs_error_exit`/`bs_cli_die` или
ANSI-escape. `printf -v` — присваивание, а не вывод, и считается отдельно.
Тела heredoc пропускаются.

Скрипт намеренно работает как **инвентарь, а не гейт CI**: текст справки и
данные остаются без цвета намеренно, и отличить их от пропущенной подписи
может только человек. Для узкого прохода — те же примитивы через ripgrep:

```bash
rg -n '^[[:space:]]*(printf|echo|print|printn|eprint|eprintn|tty_print)[[:space:]]' bootstrap lib
```

## 2. Решить, что красить

Красьте **значение** (или вердикт), оставляя подпись читаемой:

| Цвет | Примеры |
| --- | --- |
| зелёный | здоровое состояние, локальная установка, совпадающий коммит |
| жёлтый | предупреждение, системная установка, изменившийся коммит |
| красный | ошибка, повреждённый манифест |
| голубой/пурпурный | пути, коммиты, нестандартные виды установки |
| без цвета | справка/usage, машинный вывод вроде `env`, данные в файл |

Не красьте строку целиком «для красоты»: рамки, таблицы и логи считают ширину
по символам, и ANSI-escape её сломает.

## 3. Применить существующим helper'ом

В pre-kernel POSIX-части CLI (`bootstrap/cli.sh`) оборачивайте значение:

```bash
printf '  %-10s %s\n' "path:" "$(bs_cli_paint path "${__bs_cli_isrc:-?}")"
```

`bs_cli_paint <kind> <text>` живёт рядом с `bs_cli_color_on`
(`bootstrap/cli.sh:262`, paint — `:284`); таблица видов — его `case` на `:289`:
`local`, `system`, `custom`, `checkout`, `path`, `commit`, `commit_same`,
`commit_diff`, `bad`, `warn`. Новый вид добавляйте туда, а не пишите сырые
escape'ы в месте вызова.

В `lib/`:

- сообщения — через `bs_log_info|warn|error|success` (цвет, уровень и формат
  задаёт логгер);
- отдельное значение вручную — `presentation::colorize` с константой
  `PRESENTATION_COLOR_*` (`lib/ui/presentation.sh:183`);
- TUI-код — примитивы `tui::`/`wiz::`, а не собственные escape'ы.

Сырой `\033` допустим только в слое абстракции. После правки escape'ов
запускайте ANSI-чекер:
`bash .agents/skills/bs-check-ansi/scripts/check_ansi.sh`.

## 4. Соблюдать общий гейт

Гейт общий и уже реализован — не проверяйте терминал заново в своей функции:

- `NO_COLOR` (задан и непуст) выключает цвет;
- `BS_LOG_COLOR=always|never|auto` переопределяет проверку терминала;
- `auto` (по умолчанию) красит только когда stdout — терминал.

### Ловушка `$(...)`

`$(bs_cli_paint …)` выполняется в подстановке команды, где stdout — **труба**,
поэтому `[ -t 1 ]` внутри подстановки всегда ложно. Именно поэтому
`bs_cli_color_on` использует `__bs_cli_color_tty`, записанный один раз при
загрузке `bootstrap/cli.sh`, до любых подстановок. Сохраняйте это правило для
новых helper'ов: состояние tty решается при загрузке, а потом читается.

Рамки и блоки, которые меряют текст, собирайте без цвета: снимайте блок с
`BS_CLI_INFO_NO_COLOR=1` (см. `bootstrap/cli.sh:910`), а ширину считайте по
чистой строке через `bs_str_width`.

## 5. Проверить оба мира

```bash
# терминал: ANSI должен быть
script -q -c './bs version --full' /dev/null | cat -v

# труба: ANSI быть не должно
./bs version --full | cat -v

# явные гейты
NO_COLOR=1 ./bs version --full | cat -v
BS_LOG_COLOR=always ./bs version --full | cat -v   # цвет даже в трубе
```

Юнит-тесты делают то же самое: команда под `script` для цветного случая и
через обычную трубу для бесцветного; pty-случай честно пропускается, если
`script` не может создать pty (см. секцию `version --full` в
`tests/unit/testuninstallsafetyunit.sh`).

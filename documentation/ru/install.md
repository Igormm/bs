# Установка

BS устанавливается модульным установщиком в корне репозитория: точка входа — [install.sh](../../install.sh), логика находится в [install/](../../install).

## Структура установщика

- [install.sh](../../install.sh) — точка входа. Проверяет структуру репозитория (`core/`, `bootstrap/`, `install/`), подключает ядро через `bootstrap/init.sh`, включает строгий режим через `utils::strict`, проверяет интерпретатор через `check_shell_environment` (проверка реального процесса, а не `$SHELL`), затем запускает `install/main.sh`.
- [install/main.sh](../../install/main.sh) — разбор аргументов, выбор режима и путей, вызов действий установки/удаления.
- [install/checks.sh](../../install/checks.sh) — проверки окружения: `is_already_installed`, `check_shell_environment`.
- [install/actions.sh](../../install/actions.sh) — `do_install` и `do_uninstall`.
- [install/notice.sh](../../install/notice.sh) — двуязычные уведомления (рамки и строки ERROR/NOTE), `BS_SYSTEM_PREFIX`, классификация `TARGET_LIB`/`TARGET_BIN`, проверки прав записи и `sudo`.
- [install/path_manager.sh](../../install/path_manager.sh) — помощники PATH: `print_path_hint`, `auto_update_path`, `update_path_bashrc`.

## Режимы

| Режим | Флаг | Префикс | Нужен root |
| --- | --- | --- | --- |
| system | (по умолчанию) | `/usr/local` (`BS_SYSTEM_PREFIX`) | только если префикс недоступен вам на запись (`sudo`) |
| local | `--local` | `~/.local` | нет |

Значения по умолчанию переопределяются переменными окружения: `PREFIX`, `BIN_DIR` (по умолчанию `$PREFIX/bin`), `LIB_DIR` (по умолчанию `$PREFIX/lib`). Пути должны быть абсолютными.

## Виды установок

| Вид | Как создаётся | Библиотека (`TARGET_LIB`) | Wrapper (`TARGET_BIN`) | Владелец | Чем обновляется |
| --- | --- | --- | --- | --- | --- |
| system | `sudo ./install.sh` | `/usr/local/lib/bs` | `/usr/local/bin/bs` | root | `bs update` (`sudo` запросит сам), `bs update --system` |
| local | `./install.sh --local` | `~/.local/lib/bs` | `~/.local/bin/bs` | вы | `bs update`, `bs update --local` |
| custom | `PREFIX=… ./install.sh` | `$LIB_DIR/bs` | `$BIN_DIR/bs` | кто запускал | `bs update --lib DIR`; также находится сама по wrapper `bs` в `PATH` |
| исходный репозиторий | `git clone` | сам репозиторий | `./bs` | вы | не установка: это **источник** обновлений, но не цель |

На одной машине может быть несколько установок сразу (например, системная и локальная). Какая из них запустится, решает порядок в `PATH`; `type -a bs` покажет все, а `bs version --full` (или `bs env`) — какая копия работает и как она установлена.

Исходный репозиторий узнаётся по `.git` или `tests/` в корне: в установленной копии их нет. `bs uninstall` отказывается удалять такой каталог, а автопоиск целей в `bs update` пропускает репозиторий, который используется как источник.

## Что куда устанавливается

- `TARGET_LIB=$LIB_DIR/bs` — файлы фреймворка: `bootstrap/`, `core/`, `lib/` и лаунчер `bs`, скопированные из репозитория.
- `TARGET_BIN=$BIN_DIR/bs` — небольшой wrapper-скрипт:

```sh
#!/bin/sh
export BS_ROOT="${TARGET_LIB}"
exec "${BS_ROOT}/bs" "$@"
```

Wrapper — POSIX `sh` (он только передаёт управление), экспортирует `BS_ROOT` и делегирует вызов настоящей точке входа `bs`, поэтому shebang `#!/usr/bin/env bs` работает в пользовательских скриптах, как только `BIN_DIR` добавлен в `PATH`. Если на машине нет `/bin/sh` или `/usr/bin/env` (Termux), установщик и `bs update` подгоняют первую строку wrapper'а и копии `bs` под эту машину (`bs shebang`, раздел «Termux и shebang» ниже).

Автодополнение bash ставится в `~/.local/share/bash-completion/completions/bs` (`--local`), в `/usr/share/bash-completion/completions/bs` (системная установка с префиксом по умолчанию) или в `$PREFIX/share/bash-completion/completions/bs` (свой `PREFIX`, например Termux). Не получилось установить — это замечание, а не ошибка: `bs` работает и без него.

## Манифест установки

`install.sh` записывает `<TARGET_LIB>/.install` (обычные строки `ключ=значение`), чтобы копия всегда знала, как она установлена:

| Ключ | Значение |
| --- | --- |
| `mode`, `prefix`, `lib`, `bin` | режим (`system`/`local`/`custom`) и пути установки |
| `version` | версия BS установленных файлов |
| `source`, `source_repo`, `source_commit` | откуда запускался установщик: каталог, URL `origin`, коммит |
| `installed_at`, `installed_by` | время и пользователь |
| `updated_at`, `updated_from`, `updated_commit` | пишет `bs update`: когда, из какого каталога или `URL@ref`, какой коммит |

`bs env` печатает манифест, `bs version --full` — краткую сводку, `bs uninstall` берёт из него путь к wrapper. У копии, установленной старым установщиком, манифеста нет — `bs update` создаст его.

## Использование

Системная установка (действие по умолчанию — `install`):

```bash
sudo ./install.sh
sudo ./install.sh install
```

Локальная установка, без sudo:

```bash
./install.sh --local
./install.sh --local install
```

Собственный префикс:

```bash
PREFIX=/opt/bs sudo ./install.sh
```

## Безопасность: чего установщик не трогает

Установщик никогда не удаляет и не перезаписывает то, что не является BS. Перед изменением `TARGET_LIB` и `TARGET_BIN` он классифицирует оба:

| Что найдено | `install` | `uninstall` |
| --- | --- | --- |
| ничего | устанавливает | уведомление «удалять нечего», код 0 |
| установка BS (есть `bs` и `bootstrap/init.sh`, либо манифест BS) | останавливается с уведомлением «УЖЕ УСТАНОВЛЕНО»: обе версии и вывод — есть ли обновление, версия та же или установленная новее; сначала команда обновления из репозитория (`./bs update --local`, ей не нужен `PATH`), затем команда установленной копии; предупреждение, если `bs` нет в `PATH` этой оболочки (с исправлением) или первой запускается другая копия `bs`; удаление и установка и другой `PREFIX` как альтернативы; код 1 | удаляет |
| lib без wrapper или wrapper без lib | чинит переустановкой после уведомления «НЕПОЛНАЯ УСТАНОВКА — ЧИНИМ» с перечнем найденного | удаляет, что есть, и сообщает, чего не было |
| чужой каталог, файл или симлинк в роли `TARGET_LIB`; исходный репозиторий (`.git` или `tests/`) | ERROR «не установка BS», ничего не удалено; код 1 | уведомление «удалять нечего» / «часть не удалена», чужое остаётся; код 0 |
| чужой файл в роли `TARGET_BIN` (нет строки `export BS_ROOT=`) | ERROR, файл не перезаписан; код 1 | остаётся на месте, с уведомлением |
| wrapper другой живой установки BS | ERROR с его путём и версией и подсказкой `bs update --lib …`; код 1 | остаётся на месте, с уведомлением |
| wrapper, указывающий в никуда (stale) | перезаписывается, с уведомлением | удаляется |

Установка транзакционная: файлы копируются во временный каталог рядом с целью и переименовываются на место; прежняя копия сначала откладывается в сторону и возвращается, если что-то пошло не так, а ERROR называет настоящую причину (например, сообщение `cp`). Неудавшаяся установка не оставляет наполовину удалённую прежнюю.

Прочие условия, которые останавливают запуск или поясняются:

- **Нет прав записи.** Проверяется «может ли пользователь писать в `BIN_DIR`/`LIB_DIR`», а не «root ли он»: `PREFIX=/opt/x ./install.sh` работает без root, если `/opt/x` ваш; иначе ERROR с подсказками `sudo ./install.sh`, `./install.sh --local` и `PREFIX=$HOME/opt/bs`.
- **`sudo ./install.sh --local`.** Отклоняется, если `HOME` — домашний каталог `SUDO_USER` (файлы в вашем домашнем каталоге стали бы принадлежать root): запускайте без `sudo`. При `HOME=/root` только предупреждает, что установка для root, а не для `SUDO_USER`.
- **Есть другая установка** (системная при установке локальной и наоборот): уведомление «ЕСТЬ ДРУГАЯ УСТАНОВКА» называет её путь и версию и сообщает, какая копия будет запускаться `bs` по порядку в `PATH`; после удаления — «ОСТАЛАСЬ ДРУГАЯ УСТАНОВКА».
- **`BIN_DIR` не в `PATH`:** подсказка с точной строкой `export`; для локальной установки с нестандартным `BIN_DIR` автоматическая правка rc-файла пропускается, с объяснением причины.
- **Неверный ввод:** не задан или недоступен для записи `HOME`, относительный `PREFIX`, запрещённые символы (`"`, `$`, `\`) в пути, `BIN_DIR` равен `LIB_DIR`, неполный источник (список недостающего) — везде двуязычный ERROR вместо сырого сообщения оболочки.
- **rc-файлы:** недоступный для записи `~/.bashrc` не обрывает установку (предупреждение и строка для ручного добавления); удаление правит файл на месте, сохраняя симлинк на dotfile и владельца, и оставляет строку PATH, пока стоит стандартная локальная установка.

`BS_SYSTEM_PREFIX` (по умолчанию `/usr/local`) задаёт «системную» установку: библиотека `$BS_SYSTEM_PREFIX/lib/bs`, wrapper `$BS_SYSTEM_PREFIX/bin/bs`. Она нужна, чтобы воспроизводить системный случай без root; в обычной работе не задавайте. Тестовые переменные `BS_INSTALL_FAKE_EUID` и `BS_INSTALL_SUDO_HOME` меняют только формулировки отказов, но не настоящие проверки прав.

## Обновление: `bs update`

`bs update` копирует `bootstrap/`, `core/`, `lib/` и лаунчер `bs` в установленные копии без переустановки. `examples/`, `tests/` и документация **не копируются**: скрипты из репозитория запускаются из репозитория.

Результат определяют два независимых выбора: **куда ставить** (цель) и **откуда брать код** (источник).

| Флаг | Выбор |
| --- | --- |
| *(без флага цели)* | цель: все найденные установки — `~/.local/lib/bs`, `/usr/local/lib/bs`, копия, из которой запущен `bs`, и копия за wrapper `bs` в `PATH` |
| `--local` | цель: только `~/.local/lib/bs` |
| `--system` | цель: только `/usr/local/lib/bs` |
| `--lib DIR` | цель: только `DIR` (можно повторять вместе с остальными) |
| *(без флага источника)* | источник: репозиторий в текущем каталоге (есть `bs`, `core/` и `tests/`), иначе репозиторий, из которого запущен `bs`; если репозитория нет — **GitHub** |
| `--from DIR` | источник: этот каталог |
| `--github` | источник: GitHub, ветка `main` |
| `--ref REF` | источник: GitHub, эта ветка или тег (подразумевает `--github`) |
| `--pull` | перед всем остальным перемотать вперёд локальный репозиторий (`git pull --ff-only`); от флагов источника не зависит |
| `--repo URL` | источник: другой репозиторий (подразумевает `--github`); значение по умолчанию задаётся в `BS_UPDATE_REPO` |

`--from` и `--github` несовместимы. С GitHub код берётся через поверхностный `git clone`, а без `git` — архивом через `curl`/`wget`.

### Четыре частые команды

| Команда | Локальная установка (`~/.local/lib/bs`) | Системная установка (`/usr/local/lib/bs`, root) |
| --- | --- | --- |
| `bs update` | обновляет её из репозитория в текущем каталоге, иначе с GitHub | то же, через `sudo` (в терминале спросит пароль; без терминала только предупредит `not writable`) |
| `bs update --local` | то же самое: других установок нет | **ничего не делает и объясняет**: «локальной установки нет, но найдена системная: … → `bs update --system` или `bs update`», код выхода 1 |
| `bs update --local --github` | обновляет её с GitHub | сначала скачает архив, затем покажет то же уведомление (код выхода 1) |
| `bs update --github` | обновляет её с GitHub | обновляет её с GitHub, через `sudo` |

Для системной установки нужны команды без `--local` либо `--system`. Если вы уже root (`sudo bs update`), файлы копируются напрямую, без второго `sudo`; при этом `~` может оказаться `/root` (зависит от настроек `sudo`), и тогда `~/.local/lib/bs` — это каталог самого root.

### Локальный репозиторий или GitHub

Если источник — git-репозиторий, `bs update` сначала сравнивает его `HEAD` с удалённой веткой (`git ls-remote`, ничего не скачивается и не меняется):

- в репозитории **нет нового кода** (он отстаёт): в терминале `bs` спросит `[p]ull / [g]ithub / [l]ocal / [a]bort` (по умолчанию `p`, если репозиторий можно подтянуть, иначе `g`); без терминала или с явным `--from` предупредит, назовёт `--pull` и поставит локальный код;
- с `--github`, если рядом есть репозиторий, — предупреждение, когда в нём есть коммиты, не отправленные на GitHub, или незакоммиченные правки в `bs`, `bootstrap/`, `core/`, `lib/`: они **не** будут установлены;
- без сети сравнение пропускается.

### Установка, репозиторий и GitHub

`bs update` меняет **установку** (`bs`, `bootstrap/`, `core/`, `lib/`). Он никогда не копирует `examples/`, `tests/` и документацию и не трогает **репозиторий** (`R`), пока вы не попросили `--pull`. Скрипты вроде `bs run ~/bs/examples/send_video.sh` запускаются из репозитория, поэтому установка, обновлённая с GitHub рядом со старым репозиторием, даёт «обновил, а нового флага нет». Таблица показывает, чем заканчиваются `I` (установка), `R` (репозиторий) и `G` (GitHub):

| Ситуация | Что делает `bs update` | В итоге |
| --- | --- | --- |
| `R` отстаёт от `G`, терминал | спрашивает `[p]ull / [g]ithub / [l]ocal / [a]bort`; по умолчанию `p`, если подтянуть можно | `p`: `I = R = G`; `g`: `I = G`, `R` старый (предупреждение); `l`: `I = R` старые |
| то же без терминала | ставит ЛОКАЛЬНЫЙ код и предупреждает, называя `--pull` | `I = R`, оба старее `G` |
| `--pull` | `git pull --ff-only` в `R`, затем установка из `R` | `I = R = G` |
| `--github` | ставит с `G`; `R` не трогается, предупреждение об этом | `I = G`, `R` старый |
| `--github --pull` | подтягивает `R`, ставит с `G` | `I = R = G` |
| `--pull`, но в `R` есть незакоммиченные правки отслеживаемых файлов, история разошлась с удалённой, у ветки нет upstream или нет сети | отказ с причиной, код 1, ничего не меняется | без изменений |
| `--pull` и репозитория рядом нет | ошибка: запустите из каталога репозитория или укажите `--from DIR` | без изменений |
| `R` равен `G` | вопрос не задаётся | `I = R = G` |

`--pull` только перематывает вперёд: история не переписывается, ничего не сливается.

В конце каждого успешного запуска `bs update` печатает «Состояние после обновления»: установленную версию, репозиторий (путь, версия, коммит, отношение к GitHub) и вердикт — «установка и репозиторий согласованы» либо предупреждение, что репозиторий старее установки, с командой, которая это исправляет.

### Безопасность и вывод

- **Какая копия говорит.** Каждый запуск начинается с блока `Запущен / Running: bs ВЕРСИЯ`, за которым идут ровно те строки, что печатает `bs version --full`: `root:`, `install:` (режим, время и пользователь установки), `source:` (каталог и коммит) и, если обновляли, `updated:` (когда, откуда, какой коммит); для репозитория — его коммит и наличие незакоммиченных правок. Тот же блок — первые строки каждой рамки, а каждый ERROR/WARN заканчивается теми же данными в одну строку, поэтому по любому присланному куску вывода видно, какая копия `bs` его выдала; это важно, когда рядом стоят системная и локальная установки.
- **Цель проверяется до любой записи.** Принимается только установка BS (есть `bs` и `bootstrap/init.sh` либо манифест `.install`; нет `.git` и `tests/`). `bs update --lib ~/Documents` отклоняется, ничего не удаляется. Цель-симлинк разворачивается до реального пути.
- **Источник проверяется до любой записи.** Нужны `bs`, `bootstrap/init.sh`, `bootstrap/loader.sh`, `core/`, `lib/` и `core/version.sh` с читаемой версией; иначе рамка «ИСТОЧНИК НЕ ПОДХОДИТ» перечисляет недостающее, и ничего не меняется. Источник, скачанный с GitHub, проверяется так же.
- **Замена атомарна и обратима.** Старые части уходят в `.update-old.PID` внутри цели, новые ставятся на место, и новая копия должна пройти самопроверку (`bs version`, запущенный из цели). Если она не прошла, а также при SIGTERM/Ctrl-C посреди замены, прежняя версия восстанавливается, и уведомление об этом говорит. Остатки упавших запусков (`.update.PID`, `.update-old.PID`) чистятся при следующем старте, а прерванная замена тогда откатывается.
- **Одно обновление за раз.** Каталог `.update-lock` в цели не пускает второй `bs update` («уже идёт другое обновление»); замок умершего процесса перехватывается.
- Цель, идентичная источнику, помечается «уже актуально» и не трогается.
- Итог перечисляет `путь: СТАРАЯ → НОВАЯ` по каждой цели и порядок `bs` в `PATH`; установка версии старее установленной помечается `DOWNGRADE` для любого вида цели.
- Манифест обновляется (`updated_at`, `updated_from`, `updated_commit`, `version`). Повреждённый манифест сохраняется как `.install.bad` и пишется заново; отсутствующий создаётся (`mode=custom`).
- **Код выхода.** 0: обновлено или нечего делать (уже актуально, источник совпадает с целью, чужой или сломанный каталог из автопоиска пропущен). 1: явная цель не найдена или отклонена, источник отклонён, сбой копирования или самопроверки, занят замок, **или хотя бы одна цель смешанного запуска не обновилась** (после итоговой сводки).

### Сценарии и уведомления

| Ситуация | Что говорит `bs update` (RU / EN, кратко) | Код |
| --- | --- | --- |
| `--local`, есть только системная установка (и наоборот для `--system`) | «ОБНОВЛЕНИЕ НЕ ВЫПОЛНЕНО»: локальной установки нет, **но найдена системная: путь (версия) → `bs update --system` или `bs update`** | 1 |
| BS нигде не установлена | «BS НЕ УСТАНОВЛЕНА»: установок не найдено → `./install.sh --local` | 1 |
| `--system` без прав записи и без терминала | нет прав → `sudo bs update --system` | 1 |
| `--lib DIR` — чужой каталог, исходный репозиторий или файл | «не установка BS», ничего не тронуто | 1 |
| `--from DIR` не существует, не репозиторий BS или неполный; `--repo` указывает не на BS | «ИСТОЧНИК НЕ ПОДХОДИТ» со списком недостающих файлов | 1 |
| самопроверка после копирования не прошла | «самопроверка не прошла, прежняя версия восстановлена» | 1 |
| сбой копирования (нет места, нечитаемый файл) | «копирование не удалось; прежняя версия сохранена» | 1 |
| `--ref` не существует | ветка/тег `X` не найден в `<repo>` | 1 |
| нет сети, нет git и curl/wget | «репозиторий не найден / нет сети», «нужен git или curl/wget» | 1 |
| `--local` под `sudo`, у root установки нет | «вы root/sudo: `~` — домашний каталог root» и установка `SUDO_USER` → `bs update --lib <home>/.local/lib/bs` | 1 |
| обёртка `bs` в `PATH` указывает на несуществующий каталог; lib без обёртки | WARN с названием обёртки и отсутствующего каталога | 0 |
| несколько установок разных версий | сводка `путь: 0.6.0 → 0.7.1` по каждой, порядок в `PATH`, `DOWNGRADE` где нужно | 0 |
| два обновления одной цели одновременно | «уже идёт другое обновление» | 1 |
| `--from` равен цели | «источник совпадает с целью» | 0 |
| источник внутри цели или цель внутри копируемых `bootstrap/`, `core/`, `lib/` | отказ | 1 |
| `--ref` без значения, `--ref --github`, повтор `--from`/`--repo`/`--ref` с разными значениями, `--github` вместе с `--from` | отказ с причиной | 1 |

Повторный `--lib` сливается и обновляется один раз; `--local --system --lib DIR` вместе — три цели. Значения `--lib`, `--from`, `--repo` и `--ref` не могут начинаться с `-`.

```bash
bs update                     # все найденные установки, локальный репозиторий или GitHub
bs update --github            # то же, с GitHub
bs update --system            # только /usr/local/lib/bs
bs update --lib /opt/bs/lib/bs --from ~/bs
bs update --github --ref v0.7.1
bs version --full             # проверить результат
```

## Где BS на машине: `bs where`

`bs where` показывает все следы BS на машине. Команда только читает: ничего не меняет и найденные копии `bs` не запускает (версии читаются из `core/version.sh`).

| Раздел | Что показывает |
| --- | --- |
| Запущено сейчас | тот же блок, что `bs version --full` |
| Команда bs в PATH | каждый найденный в `PATH` `bs` по порядку: wrapper (и установка, куда он ведёт, с версией; отсутствующая цель помечается), лаунчер репозитория или нечто, не похожее на BS; первый помечен как запускающийся по команде `bs` |
| Установки BS | для каждой найденной: вид (local/system/custom) и версия, данные манифеста (когда и кем установлена, источник и коммит, последнее обновление), её wrapper и находится ли его каталог в `PATH`, владелец и доступ на запись (`нужен sudo`), остатки прерванных операций (`.update.*`, `.update-old.*`, `.update-lock`, `.install.bad`, `.bs.install.*`); каталог в стандартном месте, который не BS, сообщается, но не трогается |
| Репозитории BS | репозитории с версией и коммитом (в том числе названные в манифестах источником) |
| Следы в оболочке | строки в `~/.bashrc`, `~/.bash_profile`, `~/.profile`, `~/.zshrc`, `~/.zprofile`, `~/.zshenv`, конфиге `fish` и `/etc/profile*`, `/etc/zshrc`, где упоминается BS или строка `PATH` от установщика; есть ли `~/.local/bin` в `PATH` этой оболочки |
| Данные и кэш | `~/.config/bs`, `~/.cache/bs` (кэш сборок, факты, спецификации API), `~/.local/state/bs`, `~/.local/share/bs`, `BS_BUILD_CACHE_DIR` с размерами |
| Переменные окружения | `BS_SYSTEM_PREFIX`, `BS_UPDATE_REPO`, `BS_BUILD_CACHE_DIR`, `PREFIX`, `BIN_DIR`, `LIB_DIR`, если заданы |
| Итог | счётчики, затем **что вызывает вопросы** и **что сделать** с точными командами: сломанный wrapper, lib без wrapper, нет манифеста или он повреждён, остатки, установки разных версий, `bs` нет в `PATH`, запущена не та копия, что за командой `bs`, стандартное место занято не BS |

Кандидаты собираются из стандартных мест (`~/.local/lib/bs`, `$BS_SYSTEM_PREFIX/lib/bs`), запущенной копии, обёрток в `PATH`, путей `source` из манифестов и строк `source ".../bootstrap/init.sh"` в rc-файлах. `--deep` дополнительно ищет в `~`, `/opt`, `/usr/local` и `/srv` (глубина до пяти уровней, одна файловая система, не дольше 30 секунд) каталоги с `bootstrap/init.sh`.

Код выхода 0: команда сообщает, а не выносит приговор.

```bash
bs where           # всё, что BS знает о себе и своих следах
bs where --deep    # плюс поиск копий в необычных местах
```

## Удаление

```bash
sudo ./install.sh uninstall        # system
./install.sh --local uninstall     # local
bs uninstall --local               # CLI: удалить установленные копии (без правок rc-файлов)
```

`uninstall` (псевдоним: `remove`) удаляет `TARGET_BIN` и `TARGET_LIB`. В локальном режиме дополнительно удаляются `BIN_DIR`/`LIB_DIR`, но только если они пустые (`rmdir`), поэтому другие файлы в `~/.local` не затрагиваются. Также из `~/.bashrc` и `~/.zshrc` удаляется строка PATH, добавленная установщиком (только точное совпадение — пользовательские правки не трогаются).

`bs uninstall` объясняет себя так же: `--local` при одной системной установке говорит «локальной установки нет → `bs uninstall --system`» (код 1); если ничего не установлено — «УДАЛЯТЬ НЕЧЕГО» (код 1); чужой каталог, исходный репозиторий или файл в `--lib` отвергаются; без прав записи и без терминала пишет `try: sudo bs uninstall --system` и ничего не удаляет (`sudo` сам не вызывает); wrapper, принадлежащий другой установке, остаётся на месте, а lib удаляется; удаление копии, из которой запущен `bs`, объявляется как нормальное. Строка «Запущен» и здесь идёт первой.

`bs uninstall` — CLI-аналог (см. `bs uninstall --help`): удаляет дерево lib и wrapper (путь к нему берётся из манифеста), и только для каталогов, которые однозначно являются установками BS, — исходный репозиторий (есть `.git` или `tests/`) отвергается. Его можно запускать из той самой копии, которую он удаляет. rc-файлы не трогает — если нужна очистка строк PATH, запустите `./install.sh --local uninstall` из исходного репозитория.

`./install.sh uninstall` без `--local` смотрит, что установлено: если системной установки нет, а локальная есть, он удалит локальную (root не нужен) и сообщит об этом; если не установлено ничего — сообщит и завершится с кодом 0. Без root при наличии системной установки печатает ошибку вместе со справкой.

## Управление PATH (локальный режим)

Если установщик запущен из терминала и `~/.local/bin` ещё не был в `PATH` этой оболочки, в конце он запускает свежий `zsh`/`bash` (тот читает rc-файл) и печатает `PATH ПРИМЕНЁН`, так что `bs` работает сразу; `exit` возвращает в прежнюю оболочку, где `bs` появится только в новом терминале. Без терминала вместо этого печатается подсказка `source ~/.bashrc`.

После локальной установки `auto_update_path` запускается автоматически. Оба флага PATH работают только вместе с `--local`:

```bash
./install.sh --local --path         # вывести сниппет для ручной настройки
./install.sh --local --update-path  # добавить строку в ~/.bashrc и/или ~/.zshrc
```

`--update-path` дописывает следующую строку (идемпотентно — существующие идентичные строки находятся через `grep -Fqx` и не дублируются):

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Правила: `~/.bashrc` обновляется, если он существует или если нет `~/.zshrc`; `~/.zshrc` обновляется, только если уже существует. После этого перезагрузите оболочку (`source ~/.bashrc`) или откройте новую сессию.

## Termux и shebang: `bs shebang`

Shebang требует абсолютный путь. На большинстве Linux это `/usr/bin/env`; **в Termux (Android) каталога `/usr` нет**: `env` лежит в `$PREFIX/bin/env` (`/data/data/com.termux/files/usr/bin/env`). `#!/usr/bin/env bs` работает там только при установленном пакете `termux-exec`. Иначе перепишите первую строку скриптов под эту машину:

```bash
pkg install -y bash termux-exec     # проще всего: /usr/bin/env и /bin/sh начинают работать
bs shebang info                     # путь env, Termux или нет, строка каждого режима
bs shebang check ./scripts          # работает ли #! каждого файла здесь (exit 1, если нет)
bs shebang set ./scripts            # переписать под эту машину (режим auto)
bs shebang set --mode env --dry-run script.sh   # показать, что изменится
```

| Режим | Первая строка | Когда |
|---|---|---|
| `portable` | `#!/usr/bin/env bs` | скрипты, которыми делитесь; нужен `/usr/bin/env` |
| `env` | `#!<env этой машины> bs` | Termux без termux-exec |
| `abs` | `#!<полный путь bs>` | `env` нет совсем; привязано к этой установке |
| `auto` (по умолчанию) | `portable`, а без `/usr/bin/env` — `env` | большинство случаев |

`set` переписывает только файлы, чей shebang уже запускает нужную программу (`--prog`, по умолчанию `bs`), сохраняет тело и права файла; `--dry-run` ничего не меняет. Эти же функции — POSIX (`bootstrap/shebang.sh`: `bs_shebang_line`, `bs_shebang_works`, `bs_shebang_rewrite`), поэтому работают в dash, zsh и bash. Перед установщиком в Termux поставьте оболочки: `pkg install bash zsh dash busybox`; затем `bs shebang check` для установленных файлов.

## Примечания

- **Исходный каталог можно удалить.**  
  Установщик копирует файлы фреймворка в `TARGET_LIB` и создаёт обёртку в
  `TARGET_BIN`. После успешной установки BS работает из целевого каталога,
  а не из репозитория, из которого запускался `install.sh`. Целевой
  каталог зависит от режима:
  - `system` (по умолчанию): `/usr/local/lib/bs`;
  - `local` (`--local`): `~/.local/lib/bs`;
  - произвольный: значения `PREFIX`, `BIN_DIR`, `LIB_DIR`.
- **Нужен bash 4.2+** (на нём написаны ядро и вся `lib/`); установщик можно запустить из
  любой оболочки — точка входа сама найдёт bash (трамплин). Версию проверяет POSIX-пролог `install.sh`
  (`bs_shell_host_ok`, по реальному интерпретатору, а не по `$SHELL`) до всего
  остального; `init.sh` при source проверяет её ещё раз. `check_shell_environment`
  версию не проверяет: он только запоминает оболочку пользователя.
- Если BS уже установлена в целевой каталог (`is_already_installed`), установщик останавливается и предлагает сначала удалить старую версию или переопределить `PREFIX`/`BIN_DIR`/`LIB_DIR`; чтобы обновить уже установленную копию, используйте `bs update`.
- Установщик работает в строгом режиме (`utils::strict`: `set -euo pipefail`) и проверяет каждый подключаемый файл через `utils::ensure_source`.

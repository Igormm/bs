Применяй к `${component}` (команда, флаг, вывод, модуль, доки) **принцип «простота markdown»**: интерфейс не украшается, а становится прозрачным — то, что видит пользователь, говорит правду без дополнительного слоя объяснений.

## Маркдаун-тест — 7 критериев

Каждый критерий — обязательная проверка. Если дизайн проваливает критерий — упрощай, а не объясняй.

1. **Читается без рендеринга.** Команда понятна без man-страницы; вывод понятен без легенды.
   - Хорошо: `tx find "ошибка" --in app.log --regex` — ясно с первого взгляда.
   - Плохо: `bs util -xq23 --src=app.log -R` — требует справки.

2. **Ноль синтаксиса = корректный вызов.** Команда без флагов делает то, что написано «на коробке», с разумным дефолтом.
   - Хорошо: `tx count "TODO"` — литеральный поиск, вывод-суммарий.
   - Плохо: `grep TODO` без флагов молчит или ведёт себя неожиданно (regex-сюрприз).

3. **Один символ — одно значение.** Один модификатор — одно поведение, без скрытых режимов.
   - Хорошо: `--regex` включает регэксп; без него — литерально.
   - Плохо: флаг, который меняет поведение в зависимости от других флагов.

4. **Градация сложности.** 10% синтаксиса покрывают 80% задач; сложное — опционально, не по умолчанию.
   - Хорошо: 10 глаголов + ~8 общих модификаторов.
   - Плохо: 40 флагов, из которых 30 — «на всякий случай».

5. **Деградирует красиво.** Без цвета — всё ещё таблица; без `--json` — всё ещё структура; без рендерера — всё ещё текст.
   - Хорошо: вывод остаётся читаемым при `NO_COLOR=1`, в pipe, в логе.
   - Плохо: вывод полагается на цвет/ширину терминала и ломается в логе.

6. **Минимум инструментов.** Одна зависимость, без рантайма-требований; проверенное ядро не переписывается.
   - Хорошо: движок за probe-цепочкой (busybox → GNU → чистый bash).
   - Плохо: требование «установи Python 3.12 и 4 пакета».

7. **Форма отражает смысл.** Структура команды отражает структуру данных: `глагол → источник → модификатор`; вывод-таблица отражает поток строк-колонок.
   - Хорошо: `tx stats --of sales.csv --sum 3 --group 1` — глагол, источник, модификаторы по порядку.
   - Плохо: произвольный порядок аргументов, который приходится искать в справке.

## Правила применения к разным частям проекта

### Команды и флаги
- Глагол первым, источник вторым, модификаторы дальше.
- Regex — только по `--regex`; по умолчанию литерально.
- Новый флаг добавляется только если нужен двум и более глаголам/командам.
- Имена флагов — слова, не буквы: `--recursive`, а не `-R` (буквенные — только горячие клавиши в TUI).

### Вывод
- По умолчанию — таблица в духе markdown: выравнивание, суммарий («123 совпадения в 5 файлах, 2.1 мс»).
- `--json` — тот же смысл, другой рендер, не конкурент таблице.
- Пустой результат — отчёт («0 совпадений»), а не тишина.

### Ошибки
- Единая модель: код + сообщение + подсказка.
- Подсказка конкретная («проверь: ls *.log | tx pick»), не «попробуй ещё раз».
- Никакого «команда вернула 1 и все молчат».

### Код
- Имена функций/переменных читаются как предложение без комментария.
- Комментарий объясняет «почему», а не «что» (что — из имени).
- Вложенность ≤ 2-3 уровня; длинная функция — признак нехватки простоты, а не нехватки комментариев.

### Документация и примеры
- Примеры — валидные markdown-файлы: доки = примеры, примеры = доки.
- Один пункт — одна строка; таблицы вместо абзацев, где возможно.
- Каждый пример запускаем и его вывод соответствует действительности.

## Анти-примеры (что нельзя)

- `tx find --in f --regex "a.*b" --glob '*.log' --recursive --case --color --limit 5 --json --format x` — модификаторы дублируются/конфликтуют (json+table+color одновременно).
- Флаг, молча меняющий смысл другого флага.
- Команда, которая без флагов ничего не делает и требует 3 обязательных аргумента.
- Документация, где пример не совпадает с реальным выводом.

## Чек-лист перед отправкой интерфейса

- [ ] Команда читается вслух как предложение?
- [ ] Без флагов — осмысленное поведение?
- [ ] Каждый флаг — одно значение, без скрытых режимов?
- [ ] Вывод читаем в логе (без цвета) и в pipe (без интерактива)?
- [ ] Ошибка даёт код + сообщение + подсказку?
- [ ] Пример в доках запускался и соответствует выводу?
- [ ] Нет ни одного флага «на всякий случай»?

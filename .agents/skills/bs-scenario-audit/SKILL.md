# Сценарный аудит логики / Scenario-driven logic audit

Синтаксис, ShellCheck и юнит-тесты находят то, что написано неверно. **Логическая ошибка** — функция делает не то, чего ждёт пользователь: молча «успешна» при сбое, ломает состояние на полпути, по-разному ведёт себя при разных параметрах. Её находит только прогон функции по сценариям с сравнением «ожидалось / фактически».

## Карточка сценария: шесть частей, в этом порядке

| # | Часть | Что записать |
| --- | --- | --- |
| 1 | Пользовательский сценарий | кто и зачем вызывает; что должен увидеть и получить (одно предложение) |
| 2 | Основной сценарий | счастливый путь по шагам: предусловия, шаги, состояние ДО и ПОСЛЕ |
| 3 | Альтернативные сценарии | не ошибки, а другие нормальные ситуации: root или нет, TTY или нет, locale C, строгий `IFS`, `set -eu`, повторный запуск, `--dry-run`, нет необязательной программы |
| 4 | Параметры сценария | все входы: аргументы, флаги, переменные окружения, файлы, stdin, состояние системы; тип, умолчание, допустимая область |
| 5 | Полусценарий | сценарий, оборванный на полпути: сбой команды, Ctrl-C или kill, нет места или прав, обрыв сети; что осталось на диске, можно ли повторить, что увидел пользователь |
| 6 | Группы параметров | классы эквивалентности и границы: пусто, пробелы, ведущий `-`, повтор флага, взаимоисключающие флаги, относительный и абсолютный путь, симлинк, спецсимволы, юникод, очень длинное; пары комбинаций |

К каждому сценарию и каждой группе: **ожидалось** (из документации и здравого смысла) и **фактически** (команда, вывод, код возврата, состояние после). Расхождение и есть находка. Шаблон и образец: `references/scenario-card.md`.

## Протокол

0. **Безопасность, без исключений.** Всё в `T=$(mktemp -d)` с `HOME="$T/home"`, урезанным `PATH` (без `~/.local/bin` пользователя), подставными командами вместо `systemctl`, `apt`, `ip`, `sshd`, `curl`. Никакого `install.sh`, `bs update`, `bs uninstall`, записи в `~/.local`, `~/.*rc`, `/etc`, `/usr/local` на настоящей машине. Удаление только в форме `rm -rf "${T:?}"`. До и после снимать контрольную сумму установки пользователя (`find ~/.local/lib/bs ~/.local/bin -type f -exec sha256sum {} +`). Без `git commit/push/reset`.
1. **Опись.** `bash .agents/skills/bs-scenario-audit/scripts/inventory.sh [scope]` (по умолчанию `core lib bootstrap bs install install.sh`: библиотека, лаунчер и установщик): публичные функции, параметры, рискованные конструкции, покрытие тестами. Флаги `--untested`, `--min-risk N`, `--csv`.
2. **Отбор.** Сначала высокий риск без тестов: разрушающие (`rm`, `mv`, `sed -i`), привилегированные (`systemctl`, `useradd`, `iptables`), пишущие состояние (манифесты, точки остановки, конфиги). Затем остальное.
3. **Карточка** по шести частям (`references/scenario-card.md`). Не выдумывать поведение: читать код и документацию, цитировать строку.
4. **Прогон** каждого сценария и группы параметров в песочнице; записывать пару «ожидалось / фактически».
5. **Находка** с меткой класса из `references/logic-traps.md`. Для ошибки бизнес-логики нарисовать схему в две дорожки: «сценарий пользователя» и «альтернативный», в конце каждой «фактически» и «ожидалось» (красным расхождение). По схеме ошибку видно сразу. Правила, нотация и шаблон Mermaid: `references/scenario-diagram.md`.
6. **Исправление** по `systematic-debugging`: воспроизведение, затем тест, который падает, затем минимальная правка, тест зелёный, регрессия `bs-validate`, строка в `CHANGELOG.md`. Нет воспроизведения: только в список «сомнения без доказательства».
7. **Параллельно** не больше трёх агентов, у каждого свой список файлов; `CHANGELOG.md` и документацию ведёт координатор; полный `runalltests.sh` запускает только он.
8. **Отчёт** (формат ниже). Публичные имена не менять; поведение сохранять совместимым.

## Что НЕ считается находкой

Стиль, имена, комментарии без ошибки в логике; поведение, прямо описанное в документации и покрытое тестом; «могло бы быть лучше» без сценария, в котором пользователь получает неверный результат.

## Формат отчёта

```
## bs-scenario-audit: <scope>  (функций в описи: N, разобрано: M)
| # | функция | часть карточки | класс | ожидалось | фактически | серьёзность | тест |
Схема: блок ```mermaid на каждую находку с альтернативным сценарием или полусценарием
Исправлено: ...   Не исправлено (и почему): ...   Сомнения без доказательства: ...
```

Серьёзность: потеря данных или безопасность; неверный результат; вводящее в заблуждение сообщение или код возврата; косметика.

# Карточка сценария / Scenario card

Одна карточка на функцию или команду. Заполняется по коду и документации, потом
каждая строка проверяется прогоном в песочнице (SKILL.md, шаг 0).

## Шаблон

```
### <module>::<function>  (<file>:<line>)  риск: <высокий|средний|низкий>

1. Пользовательский сценарий
   Кто и зачем вызывает: ...
   Должен увидеть / получить: ...

2. Основной сценарий
   ДО:    <состояние: файлы, процессы, переменные>
   Шаги:  1) ...  2) ...  3) ...
   ПОСЛЕ: <состояние> ; код возврата: 0 ; вывод: ...

3. Альтернативные сценарии (нормальные, не ошибки)
   А1 повторный запуск        ожидалось: ...   фактически: ...
   А2 без TTY / не root       ожидалось: ...   фактически: ...
   А3 locale C, IFS=$'\n\t'   ожидалось: ...   фактически: ...
   А4 --dry-run               ожидалось: ничего не меняется   фактически: ...

4. Параметры сценария
   | имя | откуда | тип | умолчание | допустимо | недопустимо -> ожидаемая реакция |

5. Полусценарий (оборван на шаге N)
   Обрыв после шага 1 / 2 / 3:   что на диске: ...  повторный запуск: ...
   Видит пользователь: ...   ожидалось: понятное сообщение, состояние целое или откатывается

6. Группы параметров
   | группа | значения | ожидалось | фактически |
   | пусто / пробелы | "" , " " | отказ с причиной | ... |
   | ведущий минус | "-x", "--flag" | не принимается за флаг | ... |
   | повтор / конфликт | --a --a ; --a --b | ... | ... |
   | пути | относительный, со слешем, симлинк, с пробелом | ... | ... |
   | спецсимволы | * ? $ ` " ' \ ; & | ... | ... |
   | граница | 0, 1, макс, макс+1 | ... | ... |
```

## Ожидалось против фактически

Результат оформлять таблицей, расхождения помечать:

| сценарий | ожидалось | фактически | вердикт |
| --- | --- | --- | --- |
| основной | установка = репозиторий = GitHub | установка новая, репозиторий старый | РАСХОЖДЕНИЕ |

Для расхождения в бизнес-логике нарисовать схему из двух дорожек: слева «сценарий
пользователя» (шаги и состояние после каждого), справа «альтернативный»; под
каждой дорожкой пара «фактически» и «ожидалось». Узел, на котором пути расходятся,
и есть место ошибки.

## Образец (сокращённо): `bs update`, репозиторий отстаёт от GitHub

```
1. Пользователь обновляет bs и ждёт, что после этого всё на одной версии.
2. Основной: ДО I=0.7.1, R=0.7.2, G=0.7.3. Шаги: bs update -> выбор источника ->
   копирование bs, bootstrap, core, lib. ПОСЛЕ: I=G.
3. Альтернативные: --github (без вопроса), без терминала, --pull.
4. Параметры: --from, --github, --repo, --ref, --pull, --lib/--local/--system.
5. Полусценарий: обрыв во время копирования -> откат из .update-old.PID.
6. Группы: --ref без значения, --ref --github, повтор --from с разными значениями.
Находка: ожидалось I=R=G, фактически I=G, R старый (examples/ не обновились).
Класс: «состояние не согласовано» (см. logic-traps.md, раздел G). Тест: S2, S3.
```

## Как понимать «полусценарий»

Это сценарий, который начался, но не дошёл до конца: процесс убили между двумя
записями, диск кончился на третьем файле, сеть пропала посреди скачивания. Проверять
нужно три вещи: **что осталось** (файлы, блокировки, временные каталоги), **можно ли
безопасно повторить** (идемпотентность, откат, продолжение с точки остановки) и **что
сказали пользователю** (молчание или «успех» после сбоя — тоже находка).

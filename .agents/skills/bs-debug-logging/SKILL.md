Применяй к `${script}`: любой интерактивный (или просто длинный) BS-скрипт
обязан оставлять журнал при ЛЮБОМ завершении, а у тебя должен быть способ
узнать, что именно произошло.

## 1. Железное правило / The hard rule

**Невозможно завершение без лога.** Скрипт не может выйти (успех, ошибка,
отмена, краш по `set -e`, Ctrl+C) без записи в лог-файл. Реализация:
`lib/ui/steplog` — буфер + EXIT-trap + хуки:

```bash
load "lib/ui/steplog"
steplog::init "${TMPDIR:-/tmp}/<script>.log" "${verbose:-0}"
steplog::on_exit <restore_fn>   # терминал/ресурсы — через хук, НЕ через свой trap
steplog::step / steplog::ok / steplog::warn / steplog::error / steplog::info
```

- EXIT-trap принадлежит steplog — не ставь `signal::on EXIT` / `trap ... EXIT`
  после `steplog::init` (последний trap побеждает; регистрируй хук).
- `steplog::finish` сбрасывает буфер в файл — вызывается сам на EXIT.
- Строки дублируются в stderr, если включён verbose.

## 2. Ключ подробного вывода / The verbose key

Принимай `--verbose` **и** голое `verbose` (без `--`):

```bash
local verbose=0
case "${1:-}" in
    --verbose|verbose) verbose=1; shift ;;
esac
steplog::init "${TMPDIR:-/tmp}/<script>.log" "${verbose}"
```

Verbose печатает строки лога в stderr в реальном времени; журнал-файл пишется
всегда, независимо от verbose. В `--help` обязательно опиши ключ и путь к
журналу.

## 3. Инструкция по отладке BS-скрипта / How to debug a BS script

Симптом «завершился и ничего не написал» в 90% случаев — команда упала под
`set -euo pipefail`, EXIT-trap восстановил терминал, вывод скрипта потерялся.
Порядок действий:

1. **Лог-файл** — первым делом: `cat ${TMPDIR:-/tmp}/<script>.log` —
   последние строки покажут последний выполненный шаг.
2. **Verbose** — `bs run <script> --verbose 2>&1 | tee /tmp/dbg.log` —
   строки лога видны в реальном времени, ошибка видна до выхода из alt-экрана.
3. **Проверь каждую упавшую команду**:
   - `(( 0 ))`-арифметика под `set -e` → используй `$(( ))`-присваивание
     (`selected=$(( (x+1) % n ))`, не `(( selected = ... ))`);
   - `systemctl`/`useradd`/`passwd` и т.п. без проверки → оберни в
     `wiz::__apply`-подобный хелпер: `if ! "$@"; then показать рамку с
     командой и «journalctl -xe»; exit 1; fi`;
   - функции, оканчивающиеся на `A && B` → `return 0` в конце;
   - `local x="$(cmd)"` глотает код возврата → `|| true`.
4. **Воспроизведи поток** — ключи в PTY/pipe:
   `printf '\n\n\nq' | bs run <script>` — корми Enter/q по шагам и смотри,
   где поток останавливается.
5. **Терминал**: `stty size` под sudo и без TERM (ioctl работает без TERM,
   `tput` — нет); узкий/короткий терминал ломает рамки — тестируй 40x24.
6. **Тайминги ввода**: канонический режим отдаёт строку только по Enter;
   стрелки превращаются в `^[[A` — фильтруй их из значений ввода.

## 4. Чек-лист ревью

- [ ] `steplog::init` вызван в начале main; `--verbose`/`verbose` принимаются?
- [ ] Нет `signal::on EXIT`/`trap EXIT` ПОСЛЕ init (только `steplog::on_exit`)?
- [ ] Каждый шаг применения (useradd, systemctl, mkdir...) проверяет результат
      и при ошибке показывает рамку с командой, а не умирает молча?
- [ ] Отмена (`q`) и ошибка (`wiz::fail`) записываются в лог?
- [ ] В `--help` описаны `--verbose` и путь журнала?
- [ ] После прогона: файл журнала существует и содержит последний шаг?
- [ ] У всех интерактивных скриптов (визарды, TUI) правило 1 соблюдено?

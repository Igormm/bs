# UX для терминальной графики / Terminal UI UX guide

Принципы проектирования TUI-интерфейсов на BS (элементы `lib/ui/elements/`,
движки визардов, `lib/tui`). Дополняет `bs-cli-markdown-style` (простота
интерфейса) и `bs-check-ansi` (корректность эскейпов).

## 1. Компоновка / Layout

- **Центрирование по умолчанию**: диалоги и меню — по центру экрана
  (`tui::center`); статус-бар — низ, заголовок — верх. Один и тот же элемент
  не должен прыгать между позициями на разных экранах.
- **Один фокус на экран**: не более одного интерактивного элемента; остальное
  — контекст (текст, подписи).
- **Рамка всегда полная**: нижняя граница рисуется до блокирующего `read` —
  пока пользователь вводит, рамка уже завершена (см. `input.sh`).
- **Резина**: элемент обязан влезать в терминал — ширина `min(нужное, cols-4)`,
  высота `min(нужное, lines-2)`. Рамка шире экрана = перенос строк = сломанный
  вид (это был реальный баг визарда).

## 2. Цвет / Color

- **Функциональные роли, не украшение**: cyan = акцент/фокус, green = успех,
  yellow = предупреждение, red = ошибка, dim = подсказки/второстепенное.
- **Деградация**: интерфейс читаем без цвета (`NO_COLOR=1`, pipe, лог) —
  символы (▶ ✓ ●) несут смысл, цвет только усиливает.
- **Минимум цветов на экран**: 3-4 роли, не радуга.

## 3. Клавиши / Keyboard

- **Единые соглашения во всех скриптах**: ↑/↓ — выбор, Enter — OK,
  Space — переключить, q — отмена/выход, ESC — безопасный no-op (стрелка,
  разбитая задержкой, не должна выходить из приложения).
- **Цифры 1-9** — быстрый выбор в меню (без стрелок).
- **Границы безопасны**: UP на первом пункте и DOWN на последнем — no-op
  (wrap допустим только явно); арифметика через `$(( ))`-присваивание, а не
  `(( ))`-команду — иначе `(( 0 ))` под `set -e` убивает скрипт.
- **Неизвестные клавиши игнорируются** — интерфейс никогда не «падает»
  от ввода.

## 4. Состояния / States

- Каждый диалог имеет: **норма**, **фокус/выбор**, **ошибку ввода** (с
  подсказкой и повторным вопросом), **отмену** (явное сообщение: «остановился
  на шаге N», «ничего не изменено»).
- Долгие операции: **спиннер** для неопределённости, **прогресс** для
  известного объёма.
- Пустой результат — отчёт («0 совпадений»), не тишина.

## 5. Ввод / Input

- Поле ввода показывает **дефолт** и подсказку, как его принять (Enter).
- Скрытый ввод (пароль) помечается («ввод скрыт / hidden»).
- Значение валидируется сразу; ошибка — рамка с причиной и повторным вводом.
- Ввод никогда не ломает рамку: длинный текст обрезается/переносится
  осознанно.

## 6. Производительность / Performance

- Рисование в **буфер** (`tui::buf::*` + `tui::render`) — diff-рендер, без
  мерцания; один кадр < 0.1 с.
- Никаких форков в горячем цикле отрисовки: `$(...)` на каждую клавишу —
  уже заметно; массивы и строки — вместо `sed`/`awk` на кадр.
- Анимация (спиннер/прогресс) — через счётчик кадров, не через пересоздание
  буфера.

## 7. Доступность / Accessibility

- `NO_COLOR=1` — читаемый вывод.
- `TERM` без `stty`-доступа — фолбэк 80x24 и корректная резина.
- Широкие символы (CJK/эмодзи) — ширина 2 клетки; кириллица — 1.
- resize (SIGWINCH) — перерисовка кадра (в `lib/tui` — `tui::handle_resize`).

## 8. Чек-лист перед выпуском TUI-экрана

- [ ] Все элементы центрированы и не прыгают между экранами?
- [ ] Рамка полная до блокирующего ввода?
- [ ] Элемент влезает в терминал 40x24?
- [ ] Клавиши едины, границы безопасны, неизвестные игнорируются?
- [ ] Отмена сообщает шаг и что не изменено?
- [ ] Ошибки ввода — с причиной и повторным вопросом?
- [ ] Вывод читаем без цвета?
- [ ] Кадр < 0.1 с (нет форков в цикле)?
